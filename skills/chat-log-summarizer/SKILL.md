# chat-log-summarizer

## 개요

업무용 단체 대화방(카카오톡, 슬랙, Discord, Teams 등)에서 내보낸 대화 로그는 시간이 지날수록 길어지고, 결정된 내용과 잡담·중복 논의가 섞여 다시 훑어보기 번거롭다. 이 스킬은 긴 대화 로그 텍스트를 입력받아 **결정사항 / 남은 이슈 / 담당자별 할일** 3개 표로 재구성한 조회용 HTML 문서를 만든다. 목적은 "누가 뭘 언제까지 하기로 했는지"와 "아직 결론 안 난 게 뭔지"를 대화를 처음부터 다시 읽지 않고 즉시 파악하는 것이다.

트리거 예시: "이 카톡방 대화 정리해줘", "슬랙 대화 요약해줘", "이번 주 업무 대화방 로그 정리해줘", "회의 준비하게 이 대화 정리 좀"

## 언제 쓰는가

- 사용자가 카카오톡/슬랙 등에서 내보낸 텍스트 로그를 붙여넣거나 파일로 첨부하며 정리를 요청할 때
- 로그가 길어서(수십~수백 개 메시지) 사람이 다시 읽기엔 비효율적일 때
- 결정사항·할일·미결 이슈를 구조화된 형태로 다시 봐야 할 때 (회의 준비, 인수인계, 주간 정리 등)

다루지 않는 것:
- 회의 녹취록 기반 정본 회의록 작성(발언자 격식 문서) → `meeting-minutes-writer` 에이전트가 담당. 이 스킬은 자유 형식 단체방 로그를 조회용으로 가볍게 재정리하는 용도다.
- 감정 분석, 대화 참여자 평판 평가, 대화 삭제·수정 등은 다루지 않는다.

## 단계별 지침

### 1단계: 로그 형식 파악 (파싱)

업무 대화 로그는 앱마다 형식이 다르다. 정리를 시작하기 전에 반드시 원문을 훑어 아래 요소를 식별한다.

- **시간 표기**: `[오전 9:15]`, `09:15`, `2026-08-31 09:15`, 슬랙의 `9:15 AM` 등 - 앱·내보내기 설정마다 다르다.
- **발신자 표기**: 카카오톡은 보통 `[이름] [시간] 메시지` 한 줄 형식, 슬랙은 `이름  9:15 AM` 다음 줄에 메시지가 이어지는 경우가 많다. 같은 발신자가 연속 메시지를 보내면 이름이 한 번만 나오고 생략될 수 있다.
- **비메시지 라인**: "님이 들어왔습니다", "사진을 보냈습니다", "파일을 보냈습니다", 이모지 반응(리액션) 등은 결정/할일 판단에서 제외한다.
- **줄바꿈이 포함된 메시지**: 한 사람이 여러 줄을 한 메시지로 보낸 경우, 다음 발신자 표기 라인이 나오기 전까지는 같은 메시지로 취급한다.

형식이 명확히 파악되지 않으면(발신자와 시간 구분이 애매한 경우) 임의로 넘겨짚지 말고 사용자에게 어떤 앱에서 내보낸 로그인지, 형식 예시 몇 줄을 확인한다.

### 2단계: 3분할 표로 분류

전체 로그를 훑으며 아래 3가지 범주로만 분류한다. 범주에 안 맞는 잡담·인사·중복 발언은 표에 넣지 않는다.

1. **결정사항**: 대화 참여자들이 명확히 합의하거나 결론을 낸 내용. "그렇게 하죠", "네 그걸로 갑시다", "확정" 같은 동의 표현이 뒤따르는지 확인한다. 한쪽만 제안하고 답이 없으면 결정사항이 아니라 남은 이슈다.
2. **남은 이슈**: 논의는 됐지만 결론이 안 난 것. 질문에 답이 없거나, 의견이 갈렸거나, "나중에 다시 얘기하자"로 끝난 항목.
3. **담당자별 할일**: "OO님이 하기로", "제가 할게요", "~까지 보내드릴게요"처럼 담당자가 명시적으로 언급된 액션 아이템만. 담당자가 특정되지 않은 일반적 to-do는 이 표에 넣지 말고 남은 이슈 쪽으로 분류하거나 제외한다.

### 3단계: 추측 금지 원칙 (중요)

- 대화에 명시적으로 나오지 않은 담당자를 문맥상 "아마 이 사람이겠지"로 채워 넣지 않는다. 담당자가 특정되지 않았으면 **빈칸** 또는 **"미정"**으로 표기한다.
- 기한도 마찬가지다. "다음 주까지", "8/31까지"처럼 실제로 언급된 경우에만 채우고, 언급이 없으면 빈칸 또는 "미정"으로 둔다.
- 결정사항과 제안을 혼동하지 않는다. 한 사람의 제안에 다른 참여자의 명시적 동의(또는 최소한 이의 없이 넘어간 정황)가 있어야 결정사항으로 분류한다. 애매하면 결정사항이 아니라 남은 이슈로 분류한다.
- 시점(언제 결정됐는지)은 로그에 있는 시간 표기를 그대로 쓰고, 시간 표기가 없으면 "미상"으로 둔다. 정확한 시각을 추정해서 채우지 않는다.

### 4단계: HTML 산출물 생성

`assets/template.html`을 참고해 아래 스타일 규칙을 지켜 HTML을 작성한다.

- 화면 조회용 단일 HTML 파일. 표 3개(결정사항 / 남은 이슈 / 담당자별 할일)를 위에서 아래로 배치.
- 표 헤더 배경: 네이비 `#1a1a2e`, 헤더 텍스트는 흰색.
- 포인트 색상은 담당자·기한 텍스트를 강조하는 용도로만 좁게 사용한다(표 전체나 카드 배경에 넓게 쓰지 않는다).
- 3개 표는 얇은 실선(border)으로만 구분한다. 카드형 배경색·그림자로 구획을 나누지 않는다.
- 폰트: `"Malgun Gothic","맑은 고딕","Apple SD Gothic Neo","Noto Sans KR",sans-serif`
- 금지: gradient, 원형 배지, 파스텔 배지, 중첩 box-shadow, em-dash(-로 대체 또는 가운뎃점 사용)
- 서술은 개조식(명사형 종결)으로 짧게 쓴다.
- 담당자·기한 셀 텍스트는 `<strong>` 또는 지정 강조 클래스로 굵게 표시한다.
- 대화에서 언급되지 않은 담당자/기한은 빈칸이 아니라 회색 톤의 "미정" 텍스트로 표기해 누락과 구분되게 한다.

산출물은 Artifact로 발행하거나(사용자가 공유 가능한 페이지를 원할 때) 로컬 HTML 파일로 저장한다(빠른 확인만 필요할 때). 어느 쪽이든 `assets/template.html`의 구조와 스타일을 그대로 따른다.

## 참고 파일

- `assets/template.html` - 예시 대화 로그로 채워진 완성 HTML 샘플. 실제 작업 시 이 파일의 CSS와 표 구조를 그대로 재사용하고, 표 내용만 실제 대화 로그 분석 결과로 교체한다.
